# Baseline Profile: the code that starts the app and shows its first screens, compiled ahead of time instead of being
# interpreted and JIT-compiled until the system's background optimisation. Google Play compiles it when the app is
# installed or updated; for other installs, androidx.profileinstaller (pulled in by AndroidX, Compose and Coil)
# hands it to the system at the first launch, and the next background optimisation compiles it.
#
# Written as rules, not recorded: no emulator runs in CI, so there is no Macrobenchmark generator module.
# Syntax: `L<class>;` loads a class at startup; `HSPL<class>;-><method>` marks a method hot (H), used at startup (S)
# and after (P). In names, `*` matches within one package segment (not `/` nor `;`), `**` matches across packages;
# `->**(**)**` is every method of the matched classes, constructors included. The release build expands the
# wildcards against the app's classes (`expandReleaseArtProfileWildcards`), R8 renames them with the code, and
# `compileReleaseArtProfile` writes the binary profile: assets/dexopt/baseline.prof and baseline.profm in the APK,
# BUNDLE-METADATA/com.android.tools.build.profiles/ in the bundle.
#
# Maintenance: a new package or screen on the startup or browsing path gets its pair of rules below; rarely
# opened screens (settings, help, reminders, collections, categories, person) and catch-up are left to the JIT.
# To check, build the release APK and decode its profile:
#   profgen dumpProfile -p baseline.prof -a app-release.apk -m app/build/outputs/mapping/release/mapping.txt -o dump.txt
# (baseline.prof unzipped from assets/dexopt/; profgen comes with the Android SDK command-line tools).
